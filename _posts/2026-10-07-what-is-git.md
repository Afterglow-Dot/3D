## Git 是干什么的

一句话：Git 是版本控制工具。

它帮你记录项目每一次改动的版本。每改完一个阶段、觉得“这版能用”，就存一个版本。以后任何时候，都能回到任意一个版本。

它管的是**整个项目的状态**，不是单个文件。也就是说，每个版本里每个文件长什么样，它都记得清清楚楚。

你可以把它想象成游戏里的存档：打 BOSS 之前存一下，打输了读档重来。写论文、写代码、做实验记录，都一样。

## 它解决三个具体问题

**一、不怕改坏**

以前靠复制重命名：`论文_v2_最终版_真的最终版.docx`。名字越来越长，还是说不清哪版是哪个。Git 用一行提交信息取代了这堆文件名——比如“完成引言部分”“修正实验数据”，一看就懂。

**二、能看清改了什么**

`git diff` 会逐行告诉你哪几个字变了。查错的时候，比通读全文快得多。哪怕隔了一个月，也能瞬间知道上次到底动了哪里。

**三、敢做实验**

想试一个新方法，但不确定能不能成？创建一个新分支去改，成功了合并到主分支，失败了直接删除。**主线上永远是可用的版本。**

分支就像平行世界：你在里面随便折腾，都不影响主分支。测试完了，好的拿回来，不好的就删掉。

## 用与不用，差别在哪

不用 Git 的人，改代码前先备份，改完之后不敢大动，出了问题只能凭记忆一处处回退。

用 Git 的人，改之前不犹豫——因为知道随时能退回去。

这个心理上的差别，比任何技巧都重要：**它让你敢改。**

敢改，才敢试新东西；敢试，才容易进步。对于研究生来说，无论是写论文、跑实验还是整理数据，这一点都特别关键。

## 从哪开始

三条命令就能跑起来：

```bash
git add -A && git commit -m "说明这次改了什么"   # 存一版
git status                                       # 看当前状态，卡住就敲它
git log --oneline                                # 看历史
```

简单解释一下：

- `git add -A`：把所有改动放进“待提交”列表。
- `git commit -m "..."`：正式存一个版本，引号里写清楚这次改了什么。
- `git status`：随时看当前哪些文件改了、哪些还没存。
- `git log --oneline`：一行一条历史记录，看自己都存过哪些版本。

不用一次学全。先养成“改完就提交”的习惯，剩下的遇到问题再查。
